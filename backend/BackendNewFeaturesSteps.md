# Step by step guide

## 1. Create the query dir
- Go to ```backend/pkg/db/queries``` and create a new directory with the corresponding feature name
> keep it simple and clean

## 2. Create the .sql query file inside the new directory
- This file should have the same name as its parent directory
- It will contain all relevant database logic for the feature

## 3. Start writing the SQL logic
- It is important to follow the correct syntax and all relevant data types
```sql
-- name: <FunctionName> :<ReturnType>
SELECT * FROM <TableName>;
```
> sqlc return types: one, many, exec, execrows, execresult
> - one: retrieves only one instance of object from db
> - many: retrieves one or more instances of an object from db
> - exec: suitable for INSERT, DELETE, UPDATE queries when the db interaction is not that important
> - execrows: same as exec, but it returns an int64 of how many rows were affected by the query
> - execresult: same as exec, but it returns a sql.Result struct (includes LastRowID and RowsAffected)

## 4. Add the new feature/entity to sqlc.yml
- Copy the structure below and fill in the gaps accordingly
```yaml
  - engine: "sqlite"
    queries: ["/pkg/db/queries/<FeatureName>/<FeatureName>.sql"]
    schema: ["/pkg/db/migrations/sqlite/up/0000xx_create_<FeatureName>_table.sql"]
    gen:
      go:
        package: "db_<FeatureName>"
        out: "/pkg/db/queries/<FeatureName>"
```
- _IF_ feature required/has foreign keys of any nature, make sure **schema** array has all essential files inside 

## 5. Execute ```sqlc generate```
- Make sure your current working directory is where the yaml file exists
- If any errors are found by sqlc, you fix them and retry

## 6. Expose queries for easier usage
- Inside ```backend/pkg/db/sqlite/sqlite.go``` you will find the **Transactions** struct
    - Add a new field named after your feature and make its type be ***db_\<FeatureName>.Queries**
- Exactly below that struct, go inside the return of **NewQuery** func
    - Add a new return value like so:
```go
<FeatureName>: db_<FeatureName>.New(db)
```

## 7. Create route group in routes.go
- Inside ```backend/internal/routes/routes.go``` use the following pattern:
```go
func (h *Handler) <FeatureName>Routes() *http.ServeMux {
	mux := http.NewServeMux()

	// All feature related endpoints/handlers go in here

	return mux
}
```

## 8. Bind route group in setup.go
- Inside ```backend/internal/routes/setup.go``` use the following pattern:
```go
<FeatureName>Group := handler.createGroup(handler.<FeatureName>Routes, []string{})
```
> If your feature needs any new or existing middleware apart from global ones, then make sure you add them in ```{}string[]```

## 9. Add prefix to route group
- Below where you bound the route group, you will find all existing groups that are registered to the apiMux
- Use the following pattern
```go
apiMux.Handle("/<FeatureName>/", http.StripPrefix("/<FeatureName>", <FeatureName>Group))
```

## 10. Start writing the handlers logic
- Create a new .go file inside ```backend/internal/handlers```
- Use your new query functions generated by sqlc like so:
```go
<ReturnValue>, err := sqlite.NewQuery(app.DB).<FeatureName>.<NameOfFunction>(<FunctiomParams>)
```

## Important Notes

### Make sure you dont forget your validation and use ```utils/responder``` functions for HTTP responses
### For validation, you should use the ```backend/internal/helpers/inputs.go``` pattern 
### Check ```backend/internal/utils/validator.go``` for existing rules. Feel free to add any abundantly used rules of your own, else use the anonymous function method (for rules that require checking the db)
```go
"nickname": {"sometime", "string", func(v interface{}) error {
			nickname, _ := v.(string)
			_, err := sqlite.NewQuery(app.DB).Users.GetUserByNickname(r.Context(), sql.NullString{Valid: true, String: nickname})

			if !errors.Is(err, sql.ErrNoRows) {
				return errors.New("nickname exists")
			}
			return nil
		}},
```
### For UUID conversions, use ```backend/internal/helpers/uuid_convertor.go``` functions
### After you finish your handlers or if you just want to test your endpoints, use Postman with the given collection and environment which can be found inside backend/ directory and commit any changes of both so everyone can use them
